# RuleCore 语义规范

> 状态：**语法层已定稿**（§8）。实施进度见 `项目Wiki/指令核心-RuleCore/进度追踪.md`。
> 与 `Docs/我的世界谓词系统介绍.md` 的关系：那份是需求来源，这份是**语法层**的定稿。
> 改动本文件 = 改动规则语言，需要重新对齐（见 `项目Wiki/指令核心-RuleCore/进度追踪.md` 的"关键架构决策"）。

## 1. 唯一的子句形状：三元组

```
当 ⟨实体表达式⟩⟨检测⟩⟨宾语⟩ ，且 ⟨实体表达式⟩⟨检测⟩⟨宾语⟩ ，… ， ⟨实体表达式⟩⟨操作⟩⟨宾语⟩ ，且 …
```

四条硬规则：

1. **每个子句都是三元组**：主语 · 谓语 · 宾语。没有例外。
2. **逗号是唯一的段落分隔符**：逗号**之前**全是检测，**之后**全是操作。
   「当」和「且」只是渲染出来的连接词，不是语法成分。
3. **谓语只有两类**：检测（产出真/假）与操作（产出改变）。
   两者共用同一个形状、同一套槽位机制，只有语义类别不同。
4. **谓语不可省。** `地图b 下雨` 这种两词写法是歧义的——
   "在下雨"、"即将下雨"、"下雨导致湿度上升"是三条不同的检测。
   必须写成 `地图.天气 处于 下雨`。

## 2. 实体（Entity）

实体不是"东西"，而是「能出现在主语或宾语位置的指称」。

### 2.1 根

| 类 | 说明 | 例子 |
|---|---|---|
| **本主体** | 当前被评估的那个（选择器选出来的） | `本主体` |
| **本图** | 当前被评估的地图（引擎按地图实例化，规则对每张地图各跑一遍） | `本图` |
| 集合型 | 一类东西，评估时逐个取出 | `pawn` `自由殖民者` `地图` `物品` |
| 具体型 | 指到一个 | 由筛选表达式选出，如 `殖民者[不是 本主体]` |
| 字面量 | 常量 | `10` `50%` `(100,100)` `下雨` `袭击(点数=1000)` |

### 2.2 实体表达式 = 路径

```
实体表达式 := 根 ( 属性访问 | 筛选 | 归约 )*
属性访问   := '.' 属性名
筛选       := '[' 检测子句 ']'
归约       := '.' ( 第一个 | 最近 | 数量 )
```

**归约只有三个，这一条是实施时修正的**（原来列了 8 个）。原因见 §2.5：
「全部 / 任意 / 无 / 求和 / 最大 / 最小」**形状不一样**，它们不是路径上的一步。

**「打开子属性」就是这条路径上的一次 `.属性` 或 `[筛选]`。**
用户在编辑器里点开一个实体，展开的就是它**当下可用的属性与筛选**——
有子类就继续展开，没有就到此为止。这不是特例，是路径语法的自然结果。

例：

```
本主体                        —— 当前执行者
本主体.着装                   —— 他的着装（一个集合）
本主体.着装[是 帽子]           —— 其中是帽子的（可能 0 或 1 件）
本主体.着装[是 帽子].任意       —— 取一件
本主体.着装[是 帽子].任意.耐久   —— 它的耐久（0~1）
本主体.着装[是 帽子].数量       —— 有几件（数值）
本主体.位置                   —— 坐标
本图.天气                     —— 天气枚举
本图.室外温度                  —— 数值
```

### 2.3 归约必须显式写出来

```
本主体.着装[是 帽子].任意.耐久  小于  50%     —— 有一件帽子耐久低于 50% 就算成立
本主体.着装[是 帽子].全部.耐久  小于  50%     —— 所有帽子都低于 50% 才成立
本主体.着装[是 帽子].数量      大于  0        —— "穿着帽子"的正确写法
```

**这两句是两件不同的事，所以不能有默认值**——不给默认值才能逼玩家自己说清是哪一句。
编辑器在路径产生集合时**强制要求接一个归约**，求值器也会以
`path.needs_reduce` 拒绝对集合直接往下读属性。

### 2.5 量词不是归约（实施时的修正）

原来把「全部 / 任意 / 无」也列进归约算子，写代码时发现形状根本不同：

```
着装[是 帽子].第一个.耐久   小于  50%     ← 归约成单值，再比。路径上的一步。
着装[是 帽子].全部.耐久     小于  50%     ← 对**每个**元素各比一次，再合并结果。
```

后者类似 LINQ 的 `All` / `Any` / `Sum`——它需要**元素绑定**（"每个元素"在子表达式里叫什么），
是检测树上的一个量词节点，不是路径上的一步。`求和 / 最大 / 最小` 同理
（它们是把一个属性**映射**到集合上再归约，也叫 lift）。

所以第一期不做量词，用 `数量` 组合表达同样的意思：

| 想说的话 | 怎么写 |
|---|---|
| 他戴着帽子 | `着装[是 帽子].数量 大于 0` |
| 一件帽子都没有 | `着装[是 帽子].数量 等于 0` |
| 那件帽子耐久低于 50% | `着装[是 帽子].第一个.耐久 小于 50%` |
| 每件帽子耐久都低于 50% | ⚠️ 需要量词，第一期写不出来 |

**代价是可接受的**：RimWorld 里"一个槽位穿多件同类装备"极少见，集合通常只有 0 或 1 个元素，
`第一个` 和 `数量` 就能覆盖绝大多数话。真有需求时加量词节点，不动现有语法。

### 2.6 筛选器需要自己的根：`Element`

筛选 `[ 耐久 小于 50% ]` 里的"耐久"读的是**当前元素**，不是规则主体。
最初想让它"遮蔽"本主体，写到一半发现那会让这句话永远写不出来：

> 小人的血量比这件衣服的耐久高

遮蔽之后，筛选里的 `本主体` 已经变成那件衣服了。所以给元素一个**独立的根** `Element`，
主体不被遮蔽，两个名字换来的是没有歧义。

界面上它是**隐式**的：在 `[ ]` 里写的谓词，编辑器自动把主语挂上 Element 根，
玩家不需要知道它叫什么。而求值器在筛选结束后必须**把元素绑定复原**，
否则后面的兄弟节点会读到上一个元素——这条有专门的单测。

### 2.4 属性带元数据

每个属性声明：**类型**（数值 / 布尔 / 枚举 / 坐标 / 物品 / 子实体集合）、
**单位**、**范围**、**显示格式**。

`本主体.着装[是 帽子].任意.耐久` 底下是 `0.5`，但显示必须是 `50%`。
温度显示成 `12.4℃`。做不做这件事，决定了规则读起来是"人话"还是"一堆小数"。

## 3. 检测（Detect）

### 3.1 比较型（电平）

`大于` `小于` `不小于` `不大于` `等于` `不等于` `处于`

- 宾语 = 字面值、实体表达式、或取值集合
- `处于` 是集合成员：`本图.天气 处于 {下雨, 雷暴}`
- 持续成立就是持续为真（**电平**）

### 3.2 事件/状态型

`来到` `发生` `正在` `能动` `空闲` `已在`

- 一元或二元，宾语可省（`本主体 能动`）
- **边沿语义是动词自己的属性**：`来到` 声明为边沿（发生的一瞬间为真），
  `大于` 声明为电平。边沿/电平不是独立类别，玩家不该替动词作者做这个决定。

### 3.3 逻辑连接（已定：有 或 / 非 / **嵌套**）

- 检测侧是一个**布尔表达式树**：叶子是检测，节点是 `且` / `或` / `非` / 分组。
- **显式括号，不做优先级。** 有括号就不需要玩家记"非 > 且 > 或"，
  编辑器也永远把结构画出来（缩进 + 括号 + 可折叠的组），不存在"看起来是A，其实是B"。
- **操作侧只有 `且`**（顺序下发，第一个失败就停）。
  `执行A或执行B` 不是操作，是条件——要用检测写。

三个后果要知道：

1. 存储从"检测列表"变成"检测树"。渲染跟着变成缩进 + 括号 + 可折叠组。
2. 原来的"电平触发 + 零冷却"防呆警告要遍历树才能判。
3. **边沿检测放进 `或` 里**：`(袭击来到 或 虫灾来到)` 里两个边沿各开自己的时间窗，
   `或` 把它们并成一次。窗口没关时它会持续为真——靠冷却与动作幂等收束成"一次"，
   和单条边沿触发器的收束方式相同，但组合之后更容易出现"同时成立"，排障要看得出是哪一支。

### 3.4 失败模式（合并后的补偿）

生成/触发/条件三者的区别在合并后由**谓词自己声明**：

- `规则失败`：不成立 → 记 `failed`
- `安静跳过`：不成立 → 记 `capability_denied`，交回原版，**不算规则出错**
  （原来的"能力不匹配应当安静让开"就落在这里）

## 4. 操作（Operate）

### 4.1 直接改状态（God 级）

`设置`（赋值） `调整`（加减） `交换`（两实体间对调） `脱下` `穿上`

- **不会失败**，但只有开发者级规则能用
- **原版没有对应 job 的操作只能落在这里。**
  例：`脱下别人的帽子` 看着像委派，但原版没有"给清醒的人脱衣服"的 job
  （`JobDefOf.Strip` 只对尸体和倒地的人生效）→ 只能是 God 操作。
  这不是缺陷，正是把操作分三类的意义：
  **Agentic 是"原版肯替你做的事"，God 是"原版不肯但你非要"。**

### 4.2 委派（Agentic 级）

`前往` `委派工作` `拿取` `装备`

- **可能失败**（原版拒绝、路径不通、目标消失），失败即交回原版，不重试
- 只下发一次，后续走完走不完交给原版——引擎不做规划器

### 4.3 记录

`写日志`（不改变世界，排障用）

### 4.4 宾语可以是结构化字面量

`袭击(点数=1000)` 就是一个字面量，它展开成若干具名子槽。
**这是 §2.2「打开子属性」的同一个机制**，只是用在字面量上。
好处：三元组形状不变——`本图 执行 袭击(点数=1000)` 仍然是主谓宾。

## 5. 压力测试：一句自然语言

> 当小人a穿着帽子，且帽子耐久小于50%，且小人在格子（100，100），且地图a在下雨时，
> 让小人b脱掉小人a衣服，且在地图a执行一次1000袭击点袭击

### 5.1 套进三元组

```
当  本主体.着装[是 帽子].数量              大于   0
且  本主体.着装[是 帽子].任意.耐久          小于   50%
且  本主体.位置                          等于   (100,100)
且  本图.天气                            处于   下雨
，  本主体                                脱下   本主体.着装[是 帽子]
且  本图                                  执行   袭击(点数=1000)
```

**结论：能用三元组写出来。** 四处扩展都是本节已定义的内容，不是新机制。

### 5.2 但「小人b」写不出来（不起名的代价）

`小人a` → `本主体`：这个没问题，选择器选出来的那个就是"a"。
`小人b` → **没有对应物**。不起名时，另一个具体的小人只能靠筛选表达式拼：

```
殖民者[不是 本主体][离 本主体 最近]        脱下   本主体.着装[是 帽子]
```

**注意这不是起名能解决的问题**——就算起了名，名字后面挂的**还是这条路径**，
只是显示成 `小人b` 而已。所以它属于"显示别名"能覆盖的那一类（见 §5.3），
不需要为它引入一套声明机制。

另外从玩法上讲，原句的意图多半是**让小人a自己脱**（`本主体 脱下 …`），
那时完全不需要第二个实体。

### 5.3 确定性与"同一个东西"

不引入实体命名之前，必须先回答一个正确性问题：

> 条件里写的 `本主体.着装[是 帽子].任意` 和动作里写的同一串，
> 会不会选到**不同**的帽子？（条件说的和动作做的不是同一个东西）

**答案：不会，而这条保证来自已经锁定的原则，不是来自命名。**

1. **无 RNG（已锁定）** → 归约算子必须是确定性的。
2. **确定性** → 同一个世界状态、同一个表达式，求值结果必然相同。
3. 管线在**同一个 tick 内**跑完：冷却 → 权限 → 检测 → 操作 → 幂等 → 下发。
   条件与动作之间世界不会变（前一个操作的后果要到下一个采样点才影响读数）。

三条合起来，重复写同一个表达式是安全的。

**但顺带暴露一个措辞问题**：确定性的"任意"其实是"第一个匹配项"。
界面上的字叫"任意"而行为是"第一个"，是会误导人的。归约算子应该叫
`.第一个` / `.最近` / `.最大` / `.最小` ——**让字面和行为一致**。

**什么时候命名从"可读性"升级为"正确性刚需"**：
一旦引入**会随世界变化的算子**（例如 `.最近`：条件求值时最近的敌人，
到动作下发时可能换人了；中间还夹着一个会改世界的操作），
就必须靠"绑定一次、全程引用同一个"把指称钉住。到那时再加，不动语法。

### 5.4 结论：暂不做实体命名

| 维度 | 结论 |
|---|---|
| 正确性 | 不需要（由确定性 + 无 RNG + 单 tick 管线保证） |
| 可读性 | 用**显示别名**覆盖：长路径在句子里显示成 `帽子`，悬停/点开看完整路径 |
| 增量性 | 纯增量。名字只是实体表达式外面的一层外衣，任何时候加都不动语法 |
| 成本 | 一张声明表 + 名字解析 + "声明了没用"校验 + 名字间引用顺序 + 声明区 UI |

**替代方案：显示别名。** 编辑器把长路径自动折叠成语义短名
（`本主体.着装[是 帽子].第一个` → 显示 `帽子`），拿到 80% 的可读性，不付声明表的成本。

## 6. 谓词按类型过滤（不做过滤这东西就没法用）

每个谓词声明：

- 我作用于**什么类型的实体**（本主体 / 地图 / 物品 / 坐标 / 事件 / 集合）
- 我接受**什么类型的宾语**（值 / 实体表达式 / 取值集合 / 结构化字面量 / 无）
- 我是**检测还是操作**、边沿还是电平、需要什么权限层级、失败模式是什么

编辑器据此**只列出当前可用的谓词**。
不做这件事的后果：玩家面对 20 个谓词，其中 3 个能用，剩下 17 个选了之后报错。

## 7. 已拍板：触发 / 条件 / 能力合并成一张「检测」表

- **触发器本来就是检测**：`袭击来到本图` 是标准三元组。
  边沿/电平下沉到谓词声明 → `RuleTrigger` 这张表失去存在理由。
- **能力本来就是检测**：`本主体 能动` 是关于执行者的一元检测。
- 补偿办法：谓词自带 `FailureMode`（规则失败 / 安静跳过），日志上仍然分得清。
- 玩家因此只需理解**一张检测表**；加新现象只需加谓词。

## 8. 结论

语法层**全部定稿**，没有待拍板项。

- 触发 / 条件 / 能力合并成一张检测表（§7）
- 有 `或` / `非` / **显式括号嵌套**（§3.3）
- 属性算实体的一部分，可以逐层打开（§2.2）
- 不做实体命名，用显示别名代替（§5.4）
- 归约算子第一期只有 `第一个` / `最近` / `数量`（§2.5，实施时修正）
- 筛选器用独立的 `Element` 根，不遮蔽本主体（§2.6，实施时修正）

**还有一处实施时才看清的要求：实体值必须带一个"不透明把手"。**

`RuleValue` 只带"这是个 Thing"，不带"这是**哪一个** Thing"。
少了把手，宿主就没法把值翻译回游戏对象——而"归约成最近的那个"要算距离、
"脱下这件衣服"要知道是哪件。Core 不认识 Pawn / Thing，所以这个把手只能是 `object`，
Core 自己从不读它（`数量` 与 `第一个` 这类纯归约不需要知道是谁）。

## 9. 对现有代码的影响

| 现有 | 新模型下的归宿 |
|---|---|
| `RuleTrigger` + `_Always` + `_Letter` | 并成谓词：`来到`（边沿）+ `恒真` |
| `RuleCondition` + `_Always` + `_Compare` | 并成谓词：`大于`/`小于`/… + `恒真` |
| `RuleCapability` + `_Idle`/`_CanAct` | 并成谓词：`空闲`/`能动`，`FailureMode = 安静跳过` |
| `RuleValueSource`（7 个） | 变成**属性**：`本图.室外温度` `本图.降雨强度` `本主体.所在位置温度` … |
| `RuleAction` + `_Log` + `_Goto` | 并成谓词：`写日志` + `前往` |
| `RuleDestination` | 变成**宾语实体**：`最近的屋顶下` |
| `RuleSelector` | 变成`本主体`的绑定方式（`自由殖民者`） |
| `RuleOperator` | 保留，成为比较型谓词的共享参数 |
| `RuleTier` | 保留，成为谓词的属性 |
| `RuleScopeKind` | 被实体类型取代（比 Map/Pawn/Thing/Room 更宽：含事件型、坐标、集合） |

**净变化**：从"六个契约基类 × 各自的方法"变成"**一个谓词基类 + 一张按类型索引的词表 + 一条实体表达式路径**"。
代码量会**减少**——现在每种现象都要写一个类，新模型里只有新谓词才需要写类。
