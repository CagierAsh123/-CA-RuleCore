# RuleCore 词表（当前全部主谓宾）

> 这份表是**从源码 `Model/RuleVocabularyCatalog.cs` 抽出来的**，不是设计稿。
> 改词表之后要同步改这份文件。
> 生成时间：2026-09-19 · 属性 31 · 谓词 19 · 主体绑定 7 · 归约 3 · 能力位 29

规则语言的骨架是三元组：

```
当 ⟨实体表达式⟩⟨谓语⟩⟨宾语⟩ ，… ， ⟨实体表达式⟩⟨操作⟩⟨宾语⟩ ，…
```

逗号之前全是**检测**，之后全是**操作**。三块词表的组合方式见 §6。

---

## 0. 一条硬规矩：身份不是规则里的词

**「是囚犯」「是机械族」这类判断不在词表里，而且不该在。**

理由是一条能证明的话：主体绑定已经穷尽了身份。绑成「囚犯」，那一轮里每个人的身份
就都是囚犯；点了名，那个人的身份就是定死的那一个。于是 `本主体.是囚犯`
**对任何一条规则都是恒真句**——它不提供信息，只占属性列表的位置
（曾经 21 条小人属性里有 7 条是这种）。

想写「囚犯做某事」，就把主体绑成囚犯。想知道「现在这个主体到底是什么」，
**编辑器直接写在他脸上**：

```
点名一个人
  阿珍              换一个
  阿珍 现在是：囚犯

或者，让一类人各做一遍
  自由殖民者   5 个
  囚犯         3 个
  奴隶         0 个——规则不会跑
  殖民机械族   2 个
```

这条规矩的**收益在属性列表上**：绑成机械族，列表里就没有饱食度、有着电量；
绑成殖民者，反过来。玩家一次都不用判断。

> 什么时候该把身份判断加回来：**当出现一个宽到需要再区分的绑定时**
> （比如「这张图上的所有人」）。现在没有那种绑定，所以现在它们只能是常数。

## 1. 实体：根（实体表达式的起点）

| 根 | 产出类型 | 说明 |
|---|---|---|
| **某个具体小人的名字** | 小人 | 本次求值的执行者。点了名就显示**他的名字**，不是"本主体" |
| `本图` | 地图 | 本次求值所在的地图。引擎按地图实例化，所以规则对每张地图各跑一遍 |
| `全部自由殖民者` | **一组**小人 | 后面必须接归约 |
| `全部地图` | **一组**地图 | 后面必须接归约 |
| `当前元素` | 与所属集合的元素同类型 | **只在筛选器里出现** |

## 3. 实体：归约（把一组变回单值）

| 归约 | 接受 | 产出 |
|---|---|---|
| `.数量` | 一组东西 | 数值 |
| `.第一个` | 一组东西 | 单个（确定性地取第一个） |
| `.最近` | 一组东西 | 单个（离本主体最近的） |

**手上是一组东西时，归约是强制的**：不接归约，既不能往下读属性，也不能选谓语。

> 还缺：`全部` / `任意` / `无`（量词）、`求和` / `最大` / `最小`。
> 它们不是"归约"——形状不同（要对每个元素各比一次再合并），需要元素绑定。
> 所以 **`每件帽子都耐久低于 50%` 现在写不出来**。详见 §7。

### 筛选（`[…]`）

筛选器在当前元素上开一个条件。里面是一句普通的三元组，主语固定是 `当前元素`。

例：`本主体.着装[物品.耐久 小于 50%].数量 大于 0`

| `大于` `小于` `不小于` `不大于` `等于` `不等于` | **数值** | 数值 | — | 电平 |
| `是` | **名字** | 名字（域来自主语属性） | — | |
| `为真` | **布尔** | 无 | — | |

## 5. 谓语：操作（产出改变）

| 操作 | 主语要求 | 宾语 | 所需能力 | 权限 |
|---|---|---|---|---|
| `写日志` | 任意 | 文本 | — | 玩家级 |
| `前往` | 小人 | 格子 | — | 玩家级（Agentic：下一条 job 就撒手） |
| `脱下` | 小人 | 物品 | **能穿衣服** | 开发者级（原版没有"给清醒的人脱衣服"的 job） |
| `发信件` | 地图 | 名字（全部 `LetterDef`） | — | 玩家级（只通知，不改世界） |
| **`变成`** | 地图 | 名字（全部 `WeatherDef`） | — | **开发者级**：直接改天气 |
| **`触发事件`** | 地图 | 名字（全部 `IncidentDef`） | — | **开发者级**：走原版事件系统 |

### 地图：唯一一个"不通过小人就能改变世界"的地方

这一组补的是一个真实的洞：**地图原来只有一个「写日志」**，玩家点开地图的谓语列表看到的是一行。

而地图恰恰是规则语言里唯一能直接改变世界的地方——天气、事件、游戏状态都不需要谁来执行。

`触发事件` 的两个设计决定：

1. **走原版的事件系统**（`StorytellerUtility.DefaultParmsNow` → `Worker.CanFireNow` → `TryExecute`），
   不自己拼效果。这样事件的时长、信件、难度限制、"最近刚发生过"、剧本禁用全都还在。
2. **原版说"现在不能发生"就安静让开**（记 `Rejected`，不记冷却）。
   硬塞会把玩家自己设的那些规则全部踩掉——那是"原版第一顺位"。

> **要起游戏状态为什么用「触发事件」而不是单开一个动词**：
> 原版那些状态本来就由事件造成（`IncidentWorker_MakeGameCondition`），
> 而**时长在 `IncidentDef.durationDays` 上，不在 `GameConditionDef` 上**。
> 自己塞一个 `GameCondition` 就只能猜时长——那是凭空的。
> 所以读用 `处于`、写用 `触发事件`，两边对称。

### 权限层级：Developer 就是"能直接改世界状态"

| 层级 | 含义 | 怎么拿到 |
|---|---|---|
| 玩家级 | 只能"让谁去做"，动作可失败交回原版 | 默认 |
| 开发者级 | 可直接改世界状态 | 开原版开发者模式 **或** 在模组设置里勾「允许开发者级操作」 |

一条规则的实际层级 = **它所有操作里的最高级**。所以只要有一个开发者级动作，整条规则就是开发者级。

**开关放在玩家手里而不是"跟着 dev mode 走"**：这类操作确实强，但"强"该由玩家自己决定，
不该由他有没有按开调试菜单决定——把功能藏在调试菜单后面，等于让他去猜"是不是我规则写错了"。

编辑器上会直接标出来：`开发者级` 或 **`开发者级 · 未授权`**，未授权时下面还有一句去哪儿开。
**不把它们从列表里删掉**，因为规则是**可以分享的数据**——别人可能在有授权的机器上打开它，
藏起来会让那条规则看起来像坏了。

## 6. 组合规则：什么能接什么

### 值类型必须一路对得上

```
根的类型  →  每个属性/归约/筛选  →  最终类型  →  谓语是否接受
```

| 最终类型 | 能用的检测 |
|---|---|
| 数值 | `大于` `小于` `不小于` `不大于` `等于` `不等于` |
| 名字 | `是` |
| 布尔 | `为真` |
| 单个小人 | `空闲` `能动` |
| 单个地图 | `收到信件` |
| **一组东西** | **一个都不能用 —— 先归约** |

### 宾语类型也必须对得上

| 谓语 | 宾语要什么 |
|---|---|
| 数值比较 | 数值 |
| `是` | 名字 |
| `写日志` | 文本 |
| `前往` | **格子**（不是"一个人"，也不是坐标字面量） |
| `脱下` | **物品** |

### 主体绑定：**绑定就是身份**

**绑定有两种基数，这不是细节，是两件不同的事。**

| 绑定 | 基数 | 说明 |
|---|---|---|
| 不绑定 | 整图一次 | `本主体` 读不到 → 任何读 `本主体` 的检测**永远不成立** |
| **点名一个人** | **整条规则只跑一遍** | 必须再点名**是哪一位**；句子里直接写他的名字 |
| `自由殖民者` | 每个成员各跑一遍 | 冷却与自触发环按人分开算 |
| `囚犯` | 每个成员各跑一遍 | |
| `奴隶` | 每个成员各跑一遍 | |
| `殖民机械族` | 每个成员各跑一遍 | 属性列表里**不会出现饱食度**，出现的是电量 |
| `殖民地动物` | 每个成员各跑一遍 | 不会出现理念、征召 |
| `访客` | 每个成员各跑一遍 | 有人接待、既非囚犯也非奴隶 |

> 「让所有人一起做某事」**不是一个子句能表达的**。三元组的主语永远是一个东西；
> 「每个人各做一遍」是**主体绑定**的活。

**群体绑定旁边的数字是这一轮收出了几个**：0 也要显示，因为
「绑定成囚犯而殖民地没有囚犯」正是最该被看见的状态——规则会安静地什么都不做，
而玩家只会以为自己条件写错了。

> **点名绑定的一个诚实的局限**：玩家规则住在**全局配置**里，而人的引用（`ThingID`）
> 是**每个存档各自发的**。所以「点名某人」的规则换一个存档就找不到那个人，
> 于是不触发。编辑器会把这件事说出来，而不是让规则静默地什么都不做。

### 第四维：宿主能力

类型过滤是**三维**的，加上能力位之后：

| 维度 | 决定 | 例子 |
|---|---|---|
| 实体类型 | 能不能作用在这个东西上 | `耐久` 不出现在地图上 |
| 值类型 | 这个谓语吃不吃得下它现在的值 | `大于` 不出现在小人身上（小人不是数） |
| **能力位** | **这个宿主身上这件事存不存在** | **`饱食度` 不出现在机械族身上** |

能力位共 29 个，分四组：

- **实体大类**：是小人 / 是地图 / 是物品 / 是房间 / 是格子
- **生理构成**：人形 / 机械族 / 动物 / 血肉之躯
- **需求**：心情 / 饱食 / 休息 / 电量 / 娱乐 / 舒适 / 美观
- **装备与身份与能力**：能穿衣服 / 能拿东西 / 有随身物品 / 能拥有床位 /
  殖民地成员 / 囚犯 / 奴隶 / 访客 / 敌对 / 能被征召 / 有技能 / 有理念 / 有年龄

编辑器拿**当前主体样本**去比（点名就是他本人；群体绑定取成员的并集），
缺哪一位就把那条从列表里拿掉，并在下方**说清缺的是什么**：

```
这些用不上（当前主体身上没有它们要的东西）
  饱食度  —— 缺：饱食需求
  着装    —— 缺：能穿衣服
```

**"没有它"和"你选错了主体"必须分开说**——玩家看到的是同一个短列表，
但该做的下一步完全不同。

## 7. 现在写得出 / 写不出

### 写得出

```
主体绑定：点名一个人 → 小明

当  小明.着装[物品.耐久 小于 50%].数量   大于   0
且  小明.心情                          小于   30%
且  本图.天空亮度                       小于   0.3
，  小明     前往   小明.避难格
且  小明     脱下   小明.着装[物品.耐久 小于 50%].第一个
```

```
主体绑定：殖民机械族  (2)

当  本主体.电量   小于   30%
，  本主体         前往   本主体.避难格

（属性列表里没有饱食度，也没有着装 —— 机械族没有它们。
  而且**没有一句"他是机械族"**：绑定已经说了。）
```

```
主体绑定：囚犯  (3)

当  本主体.心情   小于   20%
，  本图          写日志  有囚犯快崩溃了
```

```
主体绑定：（不绑定）

当  本图.囚犯数   小于   2
且  本图.奴隶数   等于   0
，  本图          写日志  人手不足
```

```
主体绑定：（不绑定）
（需要「允许开发者级操作」—— 见 §5）

当  本图.降雨强度   小于   0.1
，  本图             变成   下雨

当  本图.地图财富   小于   5000
，  本图             触发事件  袭击
且  本图             发信件    大威胁

当  本图             处于   日蚀
，  本图             发信件  负面事件
```

### 写不出（语法级缺口）

| 想说的话 | 为什么写不出 |
|---|---|
| **每件帽子都耐久低于 50%** | 缺量词「全部」。`.第一个.耐久 小于 50%` 只问"有一件"，不是"每一件" |
| 帽子的耐久总和 / 最大 / 最小 | 缺 lift 型归约（把属性映射到集合上再归约） |
| 殖民者数 大于 敌人数 | 宾语只能是字面量，不能是另一条实体路径（`RuleOperand` 支持，但数值谓词的宾语只收字面值） |
| 他穿的是不是某件**具体**装备 | `物品.物品类型` 比的是类型不是实例 |
| 「且」和「或」混在同一层 | 现在只能靠嵌套组（`+ 或` 会建一个缩进子块） |
| 距离 / 方向相关的判断 | 没有"距离""朝向"这类属性 |
| 技能 / 特质 / 关系 | 没有对应属性（也没有带参数的属性，比如"某技能的等级"） |
| 「某监狱里的囚犯」这种二次筛选 | 主体绑定只有整图的六类，不能按房间/区域框定 |
| 「区分访客里的商队和难民」 | 身份判断被有意移出了规则语言（§0）。窄到需要它的那类绑定还没有 |

## 8. 加新词表

三种方式：

1. **改 RuleCore**：在 `Model/RuleVocabularyCatalog.cs` 里加一行（`AddXxx`）
2. **别的 mod 注册**：用 `RuleCore.Api.RuleCoreApi`，见 `Docs/扩展注册API.md`
3. **加一个能力位**：如果新属性只对某一类宿主有意义，先给 `RuleCapability` 加一位
   （`Core/RuleSemantics.cs`），在 `RulePawnFacts.OfPawn` 里给出判据，
   再在三份语言文件里补 `RuleCore.Cap.<名字>`

加一行 = 加一种玩法。**不需要加新的条件类型或动作类型**——
「室外温度大于10」不是一种类型，它是 `属性 × 比较符 × 阈值` 的组合。

**加身份类属性之前先读 §0**：如果新绑定仍然窄到决定了身份，那身份就不该进规则语言。
